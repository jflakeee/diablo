# 디아블로 2 아이템 등급/옵션 생성 규칙 리서치

작성일: 2026-10-08
출처: http://classic.battle.net/diablo2exp/items/ (Battle.net Diablo II Item Guide, classic/LOD 기준)
목적: `prototype/game_dungeon`의 아이템 시스템(`item.gd`, `craft.gd`)을 D2 원작 규칙과
대조·보강하기 위한 참고 자료. 이 문서는 설계 확정이 아니라 **원작 규칙 정리**이며,
실제 적용 여부/범위는 별도 브레인스토밍에서 결정한다.

## 1. 아이템 등급(품질) 계층

출처: `/items/basics.shtml`

희귀도 낮음 → 높음 순서:
**Low Quality → Normal → High Quality → Magic → Rare → Set → Unique**
(Crafted는 별도 트랙: 매직 베이스에서 호라드릭 큐브로 제작)

- **Low Quality**(Cracked/Crude/Damaged 등): 내구도 약 33%, 무기 데미지 75%(내림),
  방어구 방어력 75%. **에테리얼 불가, 소켓 불가.**
- **Normal**: 마법 속성 없음. 완드/스태프/셉터/방어구는 비마법이어도 가치가 있을 수 있음.
- **Superior**(=High Quality): 방어구는 `+5~15% 추가 방어력` 및/또는 `최대 내구도 +10~15%`.
  무기는 `+5~15% 추가 데미지`(또는 `+1 최대 데미지`) 및/또는 내구도 증가와
  `+1~3 공격 등급`. **세 속성이 동시에 나오는 경우는 없음**(둘까지만 동시 스폰).
- **Magic**: 접두사/접미사 보유(2절 참고).
- **Rare**: 여러 접두사/접미사 보유, 그룹 배타 규칙 적용(2절 참고).
- **Set**: 세트 전용 고정 아이템, 부분/전체 세트 보너스(4절 참고).
- **Unique**: 고유 아이템, 방어력/데미지는 범위 내 변동, 마법 보너스 일부는 범위 내
  랜덤(5절 참고).
- **Crafted**: 매직 베이스 + 호라드릭 큐브 레시피로 제작(3절 참고).
- **Failed Set / Failed Unique**: 세트/유니크 생성 조건 미충족 시 대체 품질로 스폰
  — Failed Set은 "double durability magic"(내구도 2배 매직), Failed Unique는
  "triple durability rare"(내구도 3배 레어)로 떨어진다.

## 2. 아이템 레벨(ilvl)과 품질 레벨(qlvl)

출처: `/items/basics.shtml`

- **Qlvl(Quality Level)**: 모든 아이템에 부여되는 정수. 아이템을 "Treasure Class"
  그룹으로 분류하는 데 쓰이고, 접사 레벨 결정 공식에도 사용된다.
- 플레이어 캐릭터 레벨이 드롭 결정에 직접 쓰인다는 통념은 **틀렸다** — 아이템은
  "몬스터 레벨"과 "던전 레벨"이 오를수록 좋아진다(캐릭터 레벨 자체가 아님).

## 3. 매직 아이템 접두사/접미사 생성 규칙

출처: `/items/magic.shtml`

- 접두사/접미사 조합 확률: **둘 다 보유 25% / 접두사만 25% / 접미사만 50%**.
- 매직 아이템은 **접두사 2개, 접미사 2개를 동시에 가질 수 없다**(각각 최대 1개).
- 이름은 파란색으로 표시.
- **몬스터 드롭 시** 접사 선택 범위: `qlvl(접사 레벨) <= ilvl(몬스터 레벨) + 2`인
  접사 중에서 무작위 선택.
- **도박(갬블) 시** 접사 선택 범위: 캐릭터 레벨의 `+6 / -3` 범위 내 무작위 값과
  대조해 결정.
- **매직 레벨 보너스**: 서클릿/스태프/완드/오브는 "Magic Level"이라는 특수
  속성이 있어 더 높은 레벨의 접두사/접미사를 받을 수 있다.
- **레어 아이템의 그룹 배타 규칙**(동일 메커니즘이 레어에도 적용): 접두사/접미사는
  "그룹" 단위로 묶여 있고, **그룹당 1개만 선택 가능**. 예: `+Mana` 그룹에서 Wyrm
  (+41~60 마나)이 뽑히면 같은 그룹인 Dragon's(+31~40 마나)는 선택되지 않는다.
  단, **서로 다른 그룹**의 접두사/접미사는 같은 종류(둘 다 접두사 등)라도 함께
  선택될 수 있다 — 배타는 "같은 그룹"에만 적용.

## 4. 제작(Crafted) 아이템 규칙

출처: `/items/crafteditems.shtml`

- 베이스는 반드시 **매직 아이템**, 호라드릭 큐브로 제작. 레시피는 정확한 베이스
  타입을 요구(예: "벨트"를 요구하면 벨트 종류 전체가 아니라 특정 "Belt" 아이템).
- **고정 속성 3~4개**: 예) "5~10% Chance of Crushing Blow" 같은, 일반 매직/레어
  아이템에서는 나오지 않는 전용 속성이 섞여 있음.
- **랜덤 접두사/접미사 1~4개**, ilvl 구간별 확률표:

  | ilvl 구간 | 접사 개수별 확률 |
  |---|---|
  | 1~30 | 1개 40%, 2개/3개/4개 각 20% |
  | 31~50 | 2개 60%, 3개/4개 각 20% |
  | 51~70 | 3개 80%, 4개 20% |
  | 71+ | 4개 100% |

- **제작 아이템의 접사 레벨 결정 공식**(clvl=캐릭터 레벨, ilvl=아이템 레벨,
  qlvl=베이스 아이템 품질레벨):
  1. `ilvl = int(0.5 * clvl) + int(0.5 * ilvl)`
  2. `ilvl > 99` 이면 `ilvl = 99`
  3. `qlvl > ilvl` 이면 `ilvl = qlvl`
  4. `ilvl < (99 - int(qlvl/2))` 이면 `접사레벨 = ilvl - int(qlvl/2)`,
     그렇지 않으면 `접사레벨 = ilvl*2 - 99`
- 레시피 4계열: **Hit Power, Blood, Caster, Safety Items**(각각 별도 페이지, 이번
  리서치에서는 미조사 — 필요 시 후속 조사).

## 5. 유니크 아이템 규칙

출처: `/items/uniques.shtml`, `/items/uniquebasics.shtml`

- 베이스는 Normal/Exceptional/Elite 등급 중 하나를 따르며, **방어력/데미지
  범위는 해당 베이스 아이템과 동일한 범위**를 따른다. 마법 보너스의 범위는
  변동(랜덤 롤)될 수 있다 — 즉 유니크도 고정값이 아니라 **일부 수치는 범위 내
  랜덤**.
- 내재 추가 방어력이 있는 방어구의 방어력 계산 순서:
  1. 기본값 `maxac+1`(해당 베이스의 최대 기본 방어력 + 1)에서 시작
  2. 에테리얼이면 `+50%` 보너스를 **먼저** 적용(즉 `maxac+1`에 적용)
  3. `+% 추가 방어력`과 `+방어력`은 **마지막에, 이 순서로** 적용
- **드롭 제한**: 같은 유니크 아이템은 한 게임(세션) 내에서 몬스터/상자로부터
  **두 번 이상 드롭되지 않는다**(1게임 1개 제한). 도박으로도 나올 수 있지만
  확률이 매우 낮음.
- **소켓**: 유니크는 기본적으로 **소켓 1개만 가능**(일부 예외 있음).
  **유니크 아이템으로는 룬워드를 완성할 수 없다**(룬워드는 매직/일반 베이스만
  가능).
- 레벨 요구치(Level Requirement)는 모든 유니크에 존재.
- 일부 속성은 패치 버전에 따라 스폰 여부가 다름("1.09 이후부터만 스폰" 등) —
  이 프로젝트는 특정 패치를 재현 목표로 하지 않으므로 참고만.

## 6. 세트(Set) 아이템 규칙

출처: `/items/sets/basics.shtml`

- 녹색 이름으로 식별. 감정하면 세트를 완성하는 데 필요한 나머지 아이템 목록이
  표시됨.
- **부분 세트 보너스**: 세트 아이템을 **2개 이상** 장착하면 활성화, 골드색으로
  표시. 아이템별로 "N개 장착 시" 임계값이 다를 수 있음 — 예)
  "+150 방어력 (세트 아이템 2개)", "+50% 화염 저항 (세트 아이템 3개)".
- **중복 제한**: 같은 세트 아이템을 2개 이상 들고 있어도 부분 보너스 "개수"로
  중복 집계되지 않는다(예: 반지 2개로 "다른 부위 2개 장착" 조건을 못 채움).
- **전체 세트 보너스**: 모든 부위를 장착하면 전체 보너스를 받으며, 여기에는
  부분 세트 보너스가 **포함**된다(중첩).
- 보너스는 반드시 **장착 상태**에서만 적용 — 인벤토리/큐브/창고/비활성 무기
  슬롯에 있으면 무효.
- 여러 세트를 동시에 장착하면 **각 세트마다** 부분/전체 보너스를 모두 받을 수
  있음.
- 세트 방어구의 방어력/세트 무기의 데미지는 "샘플"로 표기되며 실제로는 변동
  가능. 단 `+X% 추가 방어력`이 붙는 아이템은 **항상 최대 방어력으로 스폰**.

## 7. 소켓(Socket) 생성 규칙

출처: `/items/socketeditems.shtml`

- 소켓 가능 최대 개수는 전체적으로 **6개**가 상한.
- **방어구**: 최대 4소켓.
- **무기**: 최대 6소켓.
- 투구/방패도 소켓 가능(구체적 상한은 페이지에 명시 안 됨 — 전체 상한 6 적용
  추정).
- 품질별 소켓 제한: **매직 최대 4소켓**, **레어 최대 2소켓**, **제작/세트/
  유니크는 대부분 1소켓 제한**(일부 세트/유니크 예외 있음).
- **난이도가 소켓 개수에 영향**: 소켓이 많이 나오길 원하면 **헬 난이도** +
  게임 후반 지역에서 파밍해야 함(정확한 확률표는 이번 조사에서 미확보).
- 소켓 추가 방법 2가지:
  1. **Act 5 첫 퀘스트**(Siege on Harrogath, Larzuk): 소켓 가능한 아이템에
     소켓을 뚫어줌.
  2. **호라드릭 큐브 레시피**로도 소켓 추가 가능.

## 8. 이 프로젝트(`item.gd`/`craft.gd`)와의 대조용 체크리스트

실제 코드 반영 여부는 이 리서치 문서의 범위가 아니다. 다음 세션에서 "D2 동일성"
작업을 재개할 때 대조 포인트로 사용할 것:

- [x] 매직 아이템 접두사/접미사 확률이 `25% 둘다 / 25% 접두사만 / 50% 접미사만`과
      일치하는가 — **2026-10-08 확인: 이미 일치**. `item.gd _apply_quality_roll()`의
      `r<0.5→접미사만 / r<0.75→접두사만 / else→둘다`가 원작과 정확히 같음. 변경 불필요.
- [x] 레어/매직 접사에 "그룹 배타" 개념이 있는가 — **2026-10-08 확인: 이미 충족**.
      `PREFIXES`/`SUFFIXES` 테이블의 그룹=스탯 구조라 `_roll_affixes()`의
      `used[stat]` 중복 방지가 곧 그룹 배타와 동일한 효과. 변경 불필요.
- [ ] 소켓 개수 상한이 품질별(매직 4 / 레어 2 / 유니크·세트 1)로 구분되는가,
      현재는 `Craft.SOCKET_COUNT`가 고정값(2)인지 확인(2026-10-04 세션 기준
      소켓 시스템 활성화 때 고정 2개로 구현했던 것으로 기억 — 재확인 필요).
      **2026-10-08: 사용자 확인 결과 소켓 레시피 장비별 세분화는 현재 보류
      (범위 밖 유지)** — 이 항목 자체도 당분간 보류.
- [x] Crafted 아이템 개념(매직 베이스 + 고정 속성 3~4개 + 랜덤 접사) —
      **2026-10-08 구현 완료**(범위를 weapon/armor 단일 범용 레시피로 축소,
      4계열 세분화는 미조사 상태라 비범위). `item.gd craft()`,
      `craft.gd can_craft/craft`. 상세: `docs/superpowers/specs/
      2026-10-08-crafted-items-design.md`.
- [x] 세트 아이템의 "부분 세트 보너스"(2개/3개 장착 시 추가 보너스) 개념이
      현재 세트 아이템 구현에 있는지 — **2026-10-08 확인: 인프라는 이미 있음**.
      `item.gd equipped_set_bonus()`가 `SET_BONUSES[set_id]`를 `required`별
      tier dictionary로 순회. 현재 세트가 2부위뿐이라 체감상 "부분=전체"처럼
      보이지만, 세트 확장 시 추가 작업 없이 다단계 tier 지원. 변경 불필요.
- [x] 유니크의 "1게임 1회 드롭 제한"이 구현에 있는지 — **2026-10-08 구현 완료**.
      `item.gd roll_drop()`에 `dropped_uniques` 딕셔너리 인자 추가, `main.gd`가
      세션 스코프 `_dropped_uniques`를 공유. 상세: `docs/superpowers/specs/
      2026-10-08-unique-drop-limit-and-reroll-cost-design.md`.
