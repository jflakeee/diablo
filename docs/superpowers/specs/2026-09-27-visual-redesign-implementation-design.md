# Ashen Depths 시각 재설계 구현 상세 설계

- 작성일: 2026-09-27
- 대상 프로젝트: `prototype/game_dungeon`
- 상태: 구현 기준안
- 범위: 캐릭터 선택, 카메라, 전투 HUD, 스킬/포션 입력, 전체 화면 패널, 아이템 라벨, 전투 피드백, 반응형 및 접근성
- 제외: 전투 수식·아이템 생성·자동 장착·자동 판매·컬렉션 데이터 규칙 변경

---

## 1. 목적과 제품 원칙

기존 게임 시스템을 유지하면서 모바일과 PC에서 각각 자연스러운 조작·가독성·화면 밀도를 제공한다.

목표 경험은 다음 세 축으로 정의한다.

1. 모바일 조작은 엄지 도달 범위와 큰 터치 표적을 우선한다.
2. 전리품과 전투 정보는 Diablo II 계열의 즉시 판독성을 유지한다.
3. 프레임·아이콘·문양·캐릭터·이펙트는 Ashen Depths의 독자 리소스를 사용한다.

디자인 성공 조건:

- 플레이 중 월드가 화면의 주인공이어야 한다.
- 생존·공격·현재 목표 외 정보는 필요할 때만 나타나야 한다.
- 모바일과 PC는 같은 데이터를 사용하되 동일한 배치를 강제하지 않는다.
- 색상 하나에만 의미를 의존하지 않는다.
- 모든 사용자 입력은 100ms 이내에 시각적 반응을 시작한다.

---

## 2. 현행 구현 분석

### 2.1 유지할 기반

- `mobile_ui.gd`에 모바일/PC 크기 상수가 분리되어 있다.
- 안전 영역을 논리 좌표로 변환하는 코드가 존재한다.
- 모바일에서 카메라 확대, PC에서 축소된 HUD를 적용하고 있다.
- 스킬 개방 여부에 따라 버튼 표시를 갱신할 수 있다.
- 인벤토리·상점·캐릭터·설정 패널은 중앙 모달 형태로 전환되었다.
- 글꼴 크기와 UI 배율을 `accessibility.gd`에서 조절할 수 있다.
- 아이템 라벨 겹침 방지, 시야 안개, 미니맵, 목격 전 몬스터 비활성화가 존재한다.

### 2.2 구조적 문제

`main.gd`가 다음 책임을 동시에 가진다.

- 월드 생성과 카메라
- HUD 노드 생성
- 모바일/PC 배치 계산
- 모달 생성과 표시 전환
- 상점·가방·컬렉션 목록 렌더링
- 텍스트 조립
- 사용자 입력 처리
- 게임 규칙 실행

이 구조에서는 UI 수정이 게임 로직 회귀를 만들기 쉽고 화면 회전·크기 변경에 대응하기 어렵다.

구체적 문제:

- `_start_game()` 시점에 한 번 계산한 `viewport` 좌표를 계속 사용한다.
- 브라우저 주소창 변화, 회전, 전체 화면 전환 뒤 재배치 계약이 없다.
- HUD가 하나의 긴 `Label`이므로 정보 위계와 부분 갱신이 불가능하다.
- 모든 모달이 비슷한 스크롤 목록이지만 공통 헤더·탭·하단 행동 영역이 없다.
- 아이템 행마다 행동 버튼을 생성해 모바일에서 밀도가 지나치게 높다.
- `CanvasLayer.transform` 배율과 카메라 확대가 서로 독립적이라 실측 화면의 빈 공간과 과대/과소 UI를 예측하기 어렵다.
- `mobile_ui.gd`의 `prefer_mobile()`은 장치 종류와 화면 형태를 하나의 불리언으로 축약한다.

### 3.2 신규 파일 책임

| 파일 | 책임 |
|---|---|
| `ui/ui_root.gd` | UI 초기화, 레이어 순서, 화면 프로필 변경 전파 |
| `ui/ui_profile.gd` | 장치가 아닌 화면 형태 기반 프로필 판정 |
| `ui/ui_tokens.gd` | 색·간격·글꼴·크기·애니메이션 상수 |
| `ui/hud_controller.gd` | 게임 상태를 HUD 표현으로 변환 |
| `ui/modal_router.gd` | 모달 하나만 열기, 뒤로 가기, 입력 차단 |
| `ui/modal_shell.gd` | 공통 헤더·탭·스크롤·하단 행동 영역 |
| `ui/loot_label_manager.gd` | 드롭 라벨 우선순위·충돌·금지영역 처리 |
| `ui/notification_feed.gd` | 판매·장착·획득·해금 알림 병합 |
| `ui/camera_profile.gd` | 화면별 확대율, 프레이밍, 데드존 |
| `ui/focus_manager.gd` | 키보드·게임패드 포커스와 터치 모드 전환 |

기존 `mobile_ui.gd`는 즉시 삭제하지 않는다. 1차 구현에서는 `UIProfile`의 호환 어댑터로 사용하고, 모든 호출 전환 후 제거한다.

### 3.3 데이터 흐름

```text
게임 시스템
  → UIStateSnapshot
  → HudController / ModalViewModel
  → 화면 컴포넌트
  → 입력 의도 signal
  → main.gd의 기존 게임 명령
```

UI는 `_gold`, `_inventory`, `_player` 같은 게임 필드를 직접 변경하지 않는다. 다음과 같은 의도 신호만 보낸다.

```gdscript
signal skill_requested(skill_id: String)
signal potion_requested(kind: String)
signal item_action_requested(item_id: String, action: String)
signal modal_requested(route: String)
signal difficulty_requested(level: int)
```

## 4. 화면 프로필과 반응형 규칙

### 4.1 프로필 정의

장치 User-Agent만으로 모바일을 판정하지 않는다.

| 프로필 | 조건 | 대표 화면 |
|---|---|---|
| `PHONE_PORTRAIT` | 종횡비 `< 0.82` | 390×844, 430×932 |
| `PHONE_LANDSCAPE` | 종횡비 `>= 1.45`, 짧은 변 `< 700` | 844×390, 932×430 |
| `TABLET` | 짧은 변 `700..1000` | 1024×768 |
| `DESKTOP` | 그 외 포인터 정밀 입력 화면 | 1280×720 이상 |

입력 방식은 프로필과 별도로 보관한다.

```text
layout profile: PHONE_PORTRAIT / PHONE_LANDSCAPE / TABLET / DESKTOP
input mode: TOUCH / POINTER_KEYBOARD / GAMEPAD
```

PC 브라우저 폭을 좁혔다고 자동으로 조이스틱을 표시하지 않는다. 최근 입력 장치가 터치이고 터치 기능이 있는 경우에만 표시한다.

### 4.2 논리 좌표

- UI 기준 논리 해상도: 960×540
- 세로 화면은 540×960 기준으로 별도 계산
- 전체 UI를 단일 `CanvasLayer.transform`으로 축소하는 대신 컨테이너와 앵커를 우선 사용한다.
- 사용자 UI 배율 범위: 0.85–1.35
- 사용자 배율 적용 뒤에도 핵심 터치 영역은 44pt 상당 이하로 내려가지 않는다.

### 4.3 안전 영역

모든 프로필에서 다음 여백을 합산한다.

```text
effective inset = OS safe area + browser visual viewport inset + design margin
design margin = phone 12 / tablet 16 / desktop 20 logical px
```

브라우저에서는 `window.visualViewport.width/height` 변화도 감지한다. 다음 이벤트에 레이아웃을 다시 계산한다.

- 창 크기 변경
- 방향 전환
- 전체 화면 진입·해제
- 브라우저 주소창 표시·숨김
- UI 배율 변경
- 접근성 글꼴 배율 변경

레이아웃 재계산은 연속 이벤트를 100ms 디바운스한다.

## 5. 카메라 상세 설계

### 5.1 기본 정책

화면에 맵 전체를 맞추지 않는다. 캐릭터의 판독 가능한 크기를 먼저 고정하고 보이는 월드 범위를 화면에 따라 확장한다.

| 프로필 | 기본 zoom | 플레이어 화면 위치 |
|---|---:|---|
| Phone Portrait | 2.15 | 중앙보다 위 8% |
| Phone Landscape | 1.75 | 중앙보다 위 3% |
| Tablet | 1.40 | 중앙 |
| Desktop | 1.15 | 중앙 |

실제 zoom은 짧은 화면 변을 기준으로 ±15% 보정하되 표 범위를 크게 벗어나지 않는다.

### 5.2 HUD 보정 프레이밍

카메라 중심은 물리 화면 중앙이 아니라 `world_safe_rect` 중앙을 따른다.

```text
world_safe_rect = viewport
                  - top HUD reservation
                  - bottom control reservation
                  - left joystick reservation
                  - right skill reservation
```

세로 모바일에서는 하단 조작부 높이를 제외한 월드 안전 영역 중앙에 플레이어를 놓는다. 이것이 현재 상단 빈 공간 문제를 제거하는 핵심 규칙이다.

### 5.3 추적과 전환

- 기본 추적 보간: 8–10Hz 체감 반응
- 플레이어 이동 데드존: 화면 짧은 변의 3%
- 순간이동: 80ms 페이드 후 즉시 재중심
- 층 이동: 150ms 암전, 맵 생성, 카메라 스냅, 200ms 페이드 인
- 강한 피격 카메라 임펄스: 최대 4px, 90ms
- 사용자 설정에서 카메라 흔들림 0/50/100% 제공

### 5.4 완료 기준

- 모바일 세로에서 배경 빈 공간이 가시 영역의 15%를 초과하지 않는다.
- 플레이어는 HUD에 가려지지 않는다.
- 전체 화면 전환 후 한 프레임 안에 잘못된 좌표로 점프하지 않는다.
- 회전 후 250ms 이내에 새 레이아웃이 안정된다.

## 6. 전투 HUD 상세 설계

### 6.1 정보 계층

#### 항상 표시

- 생명력·마나
- 포션 수량
- 개방된 액티브 스킬
- 미니맵
- 현재 목표 또는 퀘스트 한 줄

#### 상황 표시

- 대상 체력과 속성
- 재사용 대기
- 상태 이상
- 아이템 획득·자동 판매·자동 장착 결과
- 스킬북 해금

#### 패널로 이동

- 방어력·매찬·전체 옵션
- 용병 세부 수치
- 액트 진행 상세
- 웨이포인트 목록
- 자동화 임계값
- 컬렉션 랭킹

### 6.2 StatusCluster

현재 하나의 긴 `_hud Label`을 다음 컴포넌트로 분리한다.

```text
StatusCluster
├─ LifeBar
├─ ManaBar
├─ LevelBadge
├─ StatusIcons
└─ OptionalNumericText
```

- 모바일에서는 최대/현재 수치를 선택적으로 숨길 수 있다.
- 생명력 25% 이하: 테두리 맥동, 화면 가장자리 약한 적색 비네트.
- 마나 부족: 해당 스킬 버튼 청색 점멸 1회.
- 상태 이상: 아이콘 + 남은 시간 원형 마스크.

### 6.3 SkillCluster

슬롯은 고정 4개지만 잠긴 스킬 슬롯은 렌더링하지 않는다. 개방 시 슬롯이 180ms 동안 확장되어 나타난다.

상태 모델:

```text
HIDDEN → AVAILABLE → PRESSED → COOLDOWN
                    ↘ NO_MANA
                    ↘ NO_TARGET
                    ↘ OUT_OF_RANGE
                    ↘ DISABLED
```

표현 규칙:

- `AVAILABLE`: 아이콘 100%, 얇은 등급 테두리
- `PRESSED`: 92% 축소 + 밝기 상승, 80ms
- `COOLDOWN`: 시계 방향 방사 마스크 + 남은 초
- `NO_MANA`: 청색 X 표식과 150ms 흔들림
- `NO_TARGET`: 회색 표적 아이콘
- `OUT_OF_RANGE`: 적색 테두리 1회
- `DISABLED`: 45% 명도, 입력 차단

모바일 크기:

- 주 공격/1번: 76–88px
- 보조 스킬: 58–68px
- 슬롯 간격: 10–14px
- 시각 크기보다 터치 영역은 사방 4px 이상 넓게 유지

PC 크기:

- 56–64px
- 화면 하단 중앙 수평 트레이
- 아이콘 하단에 `1`, `2`, `3`, `4`
- 키 입력과 클릭이 같은 `skill_requested` 경로를 사용

### 6.4 PotionCluster

- 모바일: 좌측 조이스틱 위 또는 안쪽에 HP/MP 배치
- PC: 상태 바 인접 위치에 두고 `Q`, `W` 단축키 표시
- 수량은 아이콘 우하단 배지로 표현
- 수량 0이면 사각형 문자 대신 `0`과 빈 병 실루엣 사용
- 사용 성공 시 90ms 압축, 실패 시 좌우 3px 흔들림

### 6.5 TargetFrame

- 일반 몬스터: 이름 + 짧은 체력바
- 챔피언: 청색 표식
- 정예: 금색 프레임 + 속성 아이콘 최대 3개
- 보스: 상단 중앙 전용 대형 체력바
- 목격 전 몬스터와 시야 차단 대상은 TargetFrame 후보가 될 수 없다.

## 7. 화면별 배치 명세

### 7.1 Phone Portrait

```text
┌ Quest ───────────── Minimap ┐
│                              │
│          World               │
│                              │
│ Life/Mana          Target    │
│ Potion                       │
│     Joystick       S3  S2    │
│                    S4  S1    │
└──────────── Menu ────────────┘
```

- 상단 메뉴는 아이콘형으로 축소하거나 하나의 메뉴 버튼으로 병합한다.
- `Char/Shop/Bag` 텍스트 버튼 세 개를 월드 위에 항상 노출하지 않는다.
- 세로 화면에서 미니맵 최대 폭은 화면 폭의 28%.
- 조이스틱과 스킬 클러스터는 하단 안전 영역 안에 배치한다.

### 7.2 Phone Landscape

- 좌측 조이스틱, 우측 스킬 클러스터.
- 퀘스트는 좌측 상단 한 줄.
- 미니맵은 우측 상단.
- 메뉴는 중앙 상단 작은 버튼.
- 월드 안전 영역이 좌우 입력 영역을 제외하도록 카메라를 보정한다.

### 7.3 Desktop

- 좌측 하단 생명력, 우측 하단 마나.
- 중앙 하단 스킬 트레이.
- 우측 상단 미니맵.
- 퀘스트 추적은 좌측 또는 우측 상단 접이식.
- 가방·캐릭터·설정은 아이콘 + 키 라벨로 표시.
- 가상 조이스틱은 숨김.

## 8. ModalShell 상세 설계

### 8.1 공통 동작

- 한 번에 하나의 모달만 연다.
- 모달이 열리면 월드 입력과 스킬 입력을 차단한다.
- `Esc`, Android back, 패널 닫기 버튼은 동일한 `close_top()`을 호출한다.
- 배경은 검정 55% 딤 처리한다.
- 열기 140ms, 닫기 100ms.
- 전환 중 중복 입력을 막는다.

### 8.2 크기

| 프로필 | 크기 |
|---|---|
| Phone Portrait | 안전 영역의 100%, 모서리 없음 |
| Phone Landscape | 안전 영역의 92% × 94% |
| Tablet | 최대 900×680 |
| Desktop | 최대 1100×720 |

### 8.3 공통 영역

- Header: 제목, 자원 요약, 닫기
- Navigation: 탭 또는 좌측 카테고리
- ContentHost: 스크롤 가능 콘텐츠
- ActionBar: 현재 선택에 대한 행동

닫기 버튼의 터치 영역은 최소 48×48px로 한다.

### 8.4 Character 화면

탭:

- 장비
- 능력치
- 스킬
- 용병

모바일 장비 화면:

### 8.5 Bag 화면

탭:

- 소모품

- 보관함
- 컬렉션

목록 항목은 선택만 수행한다. `Keep/Merc/Stash/Sell/Protected` 버튼을 각 행에 모두 노출하지 않는다. 선택된 항목에 대해 하단 ActionBar가 다음 행동을 제공한다.

```text
장착 | 용병 | 보관 | 보호 | 판매
```

행 구성:

- 48px 아이콘

- 희귀도 기호

- 요구 조건 미달 표식

탭:

- 구매

- 도박

도박 결과 흐름:

```text
→ 자동 장착/보관/판매 판정
→ 결과 요약
```

자동화 설정은 단계 이름과 결과 예시를 함께 보여 준다. 예: `레어 이하 자동 판매`.

### 8.7 Collection 화면

탭:

- 발견 기록
- 보관 아이템

카드에 표시:

- 발견/미발견
- 최고 전투력
- 발견 횟수
- 옵션 최고치
- 현재 보관 여부
- 현재 장착 여부

페이지 구매는 하단 ActionBar에서 비용과 증가 슬롯을 명시한다.

## 9. 아이템 라벨 시스템

### 9.1 입력 데이터

```gdscript
class_name LootLabelRequest
var item_id: String
var world_position: Vector2
var display_name: String
var quality: String
var priority: int
var created_at: int
var distance_to_player: float
```

### 9.2 우선순위

```text
퀘스트 700
스킬북 650
유니크 600
세트 550
레어 400
매직 300
일반 200
골드/소모품 100
```

거리와 생성 시간을 더해 최종 점수를 계산한다.

```text
score = base priority
      - distance × 8
      + max(0, 120 - age_ms / 25)
```

### 9.3 배치 알고리즘

1. 월드 위치를 화면 위치로 변환한다.
2. 화면 밖 요청을 제외한다.
3. 우선순위 내림차순으로 정렬한다.
4. 후보 라벨을 아이템 위에 배치한다.
5. 이미 배치된 라벨과 겹치면 8px 단위로 위쪽 이동한다.
6. HUD 금지영역과 충돌하면 좌우 중 가까운 빈 방향으로 이동한다.
7. 최대 96px 이동해도 자리가 없으면 낮은 우선순위 라벨을 숨긴다.
8. 아이템과 라벨 사이에 얇은 연결선을 선택적으로 표시한다.

금지영역은 `HUDRoot.get_exclusion_rects()`가 제공한다.

### 9.4 노출 시간

- 드롭 직후 모든 라벨: 2.5초
- 플레이어 3타일 이내: 계속 표시
- 세트/유니크/스킬북: 8초
- 사용자 `항상 표시` 설정: 거리 내 라벨 지속

동일 소모품은 가까운 거리에서 `회복 물약 ×3`으로 묶는다.

## 10. 알림과 전투 피드백

### 10.1 NotificationFeed

동일 유형 알림은 500ms 안에 병합한다.

```text
자동 판매 3개  +28,400 G
장비 교체  낡은 검 → 잿불 도끼  +14 Power
스킬 개방  Frost Shard
컬렉션 기록 갱신  Fire Resist +1
```

- 최대 4줄
- 새 알림은 아래에서 위로 쌓임
- 일반 2.5초, 중요 4초
- 메뉴가 열려 있으면 알림은 모달 위가 아니라 보류 후 닫힐 때 요약

### 10.2 타격 피드백

- 명중: 대상 60ms 밝기 상승
- 치명타: 큰 숫자 + 테두리 + 짧은 임펄스
- 빗나감: `MISS` 중립색
- 면역: `IMMUNE` + 속성 아이콘
- 막기: 방패 아이콘 + 금속성 이펙트
- 사망: 120ms 정지감 후 소멸 또는 쓰러짐

피해 숫자는 같은 대상·같은 속성 피해가 120ms 안에 발생하면 합산한다.


난이도는 색만 사용하지 않고 설명을 함께 표시한다.

- Normal: 첫 플레이 권장

- Hell: 최고 난도와 큰 저항 페널티

### 12.2 모바일

- 타이틀은 화면 높이 8% 이내.
- 배포 시각은 제목 아래 13px 이상.
- 클래스 카드는 화면 폭 88%, 높이 최소 72px.
- 세로 공간 부족 시 소개 설명을 접고 시작 버튼은 하단 고정.

### 12.3 독자 리소스

- Iron Warden: 녹슨 철, 방패 흔적, 붉은 잿불
- Arcanist: 청자색 룬, 차가운 안개, 밝은 마력 핵
- Blizzard 원본 이미지·문양·아이콘을 사용하지 않는다.

## 13. 접근성 및 입력

- 터치 핵심 조작 최소 44×44pt 상당.
- 텍스트 대비 기본 4.5:1 목표.
- 희귀도는 색 + 프레임/기호 병행.
- UI 배율 85/100/115/130%.
- 큰 글꼴 모드에서 목록 행 높이도 함께 증가.
- 화면 흔들림, 피해 숫자, 아이템 이름 표시 방식을 각각 설정 가능.
- 키보드 포커스 표시를 숨기지 않는다.
- 키 재지정은 기존 `1–4`, WASD, 방향키와 충돌하지 않게 한다.
- 길게 누르기가 필수인 기능을 만들지 않는다.
- 소리로 알리는 사건은 시각 알림도 제공한다.

재설계는 다음 조건을 모두 만족할 때 완료로 본다.

- 모바일 세로·가로와 PC에 독립된 HUD 배치가 적용된다.
- 모바일에서 월드가 유효 게임 영역의 70% 이상을 차지한다.
- 디버그형 장문 HUD가 전투 화면에서 제거된다.
- 개방된 스킬만 보이고 모든 표시 버튼이 실제로 동작한다.
- Char/Bag/Shop/Settings가 공통 ModalShell을 사용한다.
- 아이템 20개 동시 드롭에서도 라벨과 핵심 HUD가 충돌하지 않는다.
- 깨진 한글·누락 글리프가 없다.
- UI 배율 85–130%에서 핵심 기능에 접근 가능하다.
- PC 키보드, 터치, 전체 화면, 화면 회전 회귀 테스트가 통과한다.
- 기준 해상도 시각 회귀가 통과한다.
- 기존 게임 시스템 테스트 결과가 재설계 전과 동일하다.

## 19. 첫 구현 단위

첫 변경 묶음은 기능 추가 없이 다음 네 항목으로 제한한다.

1. `UIProfile`과 화면 변경 감지
2. `CameraProfile`과 `world_safe_rect`
3. HUD 금지영역 계산
4. 기준 해상도 레이아웃 자동 검사

이 단위가 통과한 뒤 HUD 시각 컴포넌트를 이전한다. 카메라와 좌표 체계가 고정되기 전에 아이콘·프레임 에셋부터 적용하지 않는다.
