# 프리셋 룸 다양화 설계

작성일: 2026-10-01
대상: `prototype/game_dungeon`
상태: 구현 기준 확정

## 1. 목표

`level_gen.gd`의 룸은 지금까지 전부 테두리 1칸 벽에 완전히 뚫린 7x7 내부를 가진 동일한
형태였다(MODE_RANDOM/STRAIGHT/BLOCKED_RANDOM은 door·장애물 배치만 다를 뿐 룸 자체 형태는
단조롭다). 작가가 설계한 소규모 기둥 배치 프리셋을 룸마다 확률적으로 얹어 시각적 다양성을
준다.

## 2. 완료 조건

1. 각 룸은 생성 시 세 가지 중 하나로 결정된다: 무장식(50%), 안쪽 5x5 모서리 4기둥(25%),
   안쪽 5x5 십자형 4기둥(25%).
2. 어떤 프리셋을 골라도 룸 내부 테두리 1칸(문이 열리는 바로 안쪽 통로)과 중심 타일의
   상하좌우 이웃은 항상 비어 있어, 문 위치·연결 그래프와 무관하게 항상 우회로가 존재한다.
3. 프리셋은 `_carve_room` 직후(문 카빙·테마 장식·장애물 배치보다 먼저) 적용되어, act3
   (pillar_plains)처럼 룸 내부를 통째로 다시 까는 테마가 있으면 자연스럽게 덮어써진다
   (기존에도 룸의 기본 형태가 테마에 덮어써지는 것과 동일한 동작).
3. 보스룸 아레나(중앙+인접 4룸)에 프리셋이 걸려도 아레나 카빙이 항상 마지막에 실행되어
   완전히 덮어쓰므로 아레나 내부는 항상 깨끗하다.
4. 기존 연결성 보장(입구→출구, 모든 룸 중심 도달 가능)이 프리셋 적용 후에도 전 생성
   모드·전 액트 테마에서 깨지지 않는다.

## 3. 범위와 비범위

### 범위
- `level_gen.gd`: `_apply_room_preset` 신규 함수, `_generate_region`의 룸 카빙 루프에 연결
- 셀프테스트: 여러 시드에 걸친 연결성 유지 + 프리셋 등장 여부 검증

### 비범위
- 룸 형태 자체의 구조적 다양화(비정형 모양, 복도 폭 변화 등) — 이번엔 장식 수준만
- 저장 스키마 변경(생성 시점 로직만 변경, 영속 데이터 아님)

## 4. 상세 설계

### 4.1 `_apply_room_preset(grid, sx, sy, rng)`

룸 내부(로컬 좌표 1~7)의 "안쪽 5x5"(로컬 2~6)에만 기둥을 놓는다. 테두리(로컬 1, 7)는
항상 비워 둬 문이 어디에 생기든(오프셋 2~6 범위) 테두리를 따라 도는 우회로가 보장된다.

- `roll < 0.25`: 안쪽 5x5의 네 모서리 `(2,2) (6,2) (2,6) (6,6)`에 PILLAR.
- `0.25 <= roll < 0.5`: 안쪽 5x5의 네 변 중앙(중심에서 거리 2) `(4,2) (4,6) (2,4) (6,4)`에
  PILLAR. 중심 타일의 상하좌우 이웃(거리 1)은 항상 비어 있어 AStarGrid2D의 4방향 이동으로도
  중심이 고립되지 않는다.
- 그 외(50%): 무변경.

`_generate_region`의 룸 카빙 루프(`for sy: for sx: _carve_room(...)`)에서
`_carve_room` 직후 호출한다. 이 호출은 기존 `rng` 시퀀스에 룸 개수만큼의 `randf()` 호출을
추가로 소비하므로, 이후(문 오프셋, act3 기둥 산포, blocked_random 장애물) 단계의 정확한
타일 배치가 바뀐다 — 시드당 결정론은 유지되므로(동일 시드=동일 결과) 문제 없다.

### 4.2 부수적으로 발견/수정한 기존 버그

프리셋 도입으로 RNG 소비 시점이 바뀌면서, **기존에도 존재하던** act3(pillar_plains) 생성의
잠재적 연결성 버그가 테스트에서 드러났다. act3는 룸 경계를 무시하고 전역 좌표에 기둥
`slots*slots*2`개를 무작위로 흩뿌리는데, `MODE_BLOCKED_RANDOM`과 달리 이 산포에는 연결성
복구 루프가 없었다. 드물게(관측된 시드 조합 기준) 입구-출구 경로를 끊을 수 있었다.

수정: act3 산포 단계에서 실제로 PILLAR로 바뀐 셀을 `plains_pillar_cells`에 기록해 두고,
`exit_slot`이 정해진 직후(`MODE_BLOCKED_RANDOM` 복구 루프와 동일한 지점) `blocked_random`과
동일한 패턴으로 연결성이 회복될 때까지 되돌린다. 이 수정은 act3를 쓰는 모든 생성
경로(보스 유무, 생성 모드 무관)에 적용되어 프리셋과 무관하게도 안전해진다.

### 4.3 셀프테스트

- 시드 5001~5006(act1, MODE_RANDOM)으로 생성한 청크 6개가 전부 `_tile_path_exists`와
  `_all_room_centers_reachable`을 통과하는지, 그중 하나 이상에서 PILLAR가 등장하는지(act1은
  테마 자체가 장애물을 넣지 않으므로 발견되면 전부 프리셋 기여분) 확인.
- 시드 6001~6006(act3, MODE_RANDOM)으로 act3 전용 연결성 회귀를 별도로 감시.
