# 스탯/스킬 리스펙 설계

작성일: 2026-10-02
대상: `prototype/game_dungeon`
상태: 구현 기준 확정

## 1. 목표

잘못 분배한 스탯/스킬 포인트를 되돌릴 방법이 없었다. 상인 패널에 골드 소비형 리스펙
버튼을 추가한다(D2 1.13의 "속죄의 증표" 퀘스트 토큰 대신, 이 프로젝트는 골드 비용으로
각색 — 퀘스트 보상 체인을 새로 설계할 필요 없이 기존 상인 골드 경제에 바로 편입된다).

## 2. 핵심 설계 결정: 스킬은 "0"이 아니라 "1"로 리셋한다

`main.gd`의 스킬 투자 버튼(`_spend_skill`)은 `_player.skill_level(id) <= 0`이면 항상
비활성화된다 — 레벨 0인 스킬은 이 버튼으로 절대 올릴 수 없고, 오직 스킬북 드롭
(`_make_skill_book`/`_next_skill_book_drop`)을 먹어야 레벨 1로 "해금"된다. 리스펙이 모든
스킬을 레벨 0으로 되돌리면, 그 캐릭터는 스킬북을 다시 주울 때까지 환불받은 스킬 포인트를
하나도 못 쓰는 상태에 빠진다. 이는 실제 플레이에서 체감되는 회귀이며, 받아들일 이유가
없다. 그래서 리스펙은 "이미 해금된(레벨>=1) 스킬은 레벨 1로, 아직 해금되지 않은(레벨 0)
스킬은 그대로 0으로" 되돌리고, 레벨 1을 넘는 투자분만 환불한다 — 해금 상태(접근권)는
보존하고 분배(레벨)만 초기화한다.

## 3. 완료 조건

1. 상인 패널 버튼으로 골드를 지불하면 스탯이 클래스 기본값으로, 스킬이 "해금된 스킬은
   레벨 1, 미해금 스킬은 0"으로 리셋되고, 그 차이만큼 스탯/스킬 포인트가 풀로 환불된다.
2. 환불량은 항상 실제 분배 기록(현재 스탯/스킬 값 - 기준값)에서 계산한다. 레벨 공식으로
   재추정하지 않는다(퀘스트가 스킬 포인트를 추가 보상으로 주므로 `레벨 * N` 재계산은
   포인트 풀을 오염시킨다).
3. 리스펙 직후 `_recompute_player()`와 `_merc_scale_stats()`를 호출해 파생 스탯(최대
   생명력/마나/저항/용병 스탯)이 즉시 갱신된다.
4. 세이브 스키마 변경 없음 — `_player.skills`/`stat_*`/`skill_points`/`_stat_points`는 이미
   저장되는 필드이므로 새 영속 상태가 생기지 않는다.

## 4. 범위와 비범위

### 범위
- `main.gd`: `_class_base_stats()`(클래스별 기준 스탯, `_start_game`의 리터럴을 재사용하도록
  리팩터), `_respec_cost()`, `_respec()`, 상인 패널 버튼(동적 비용 표시)
- 독립 검증 모드 `_run_respec_test()` + cmdline 플래그 `respec_test`(`_run_economy_conversion_test`
  등과 동일한 패턴: 포인트 분배 → 리스펙 → 환불/기준값/재분배 가능 여부 검증 → `[RESPEC]`
  verdict 출력). 게임플레이 경로에 의존하지 않는 결정론적 테스트라 전용 모드로 분리했다
  (경제/자동장착 테스트와 동일한 선례).

### 비범위
- 퀘스트 토큰/제한 횟수형 리스펙(D2 1.13 방식) — 골드 비용 무제한 사용으로 단순화
- 스킬 "해금 취소"(스킬북으로 얻은 레벨 1 접근권 자체를 박탈하는 것) — 위 2절 참고
- 용병 스탯 리스펙(용병은 장비로만 성장, 캐릭터 스탯/스킬 트리가 없음)

## 5. 상세 설계

### 5.1 스탯 환불

`stat_refund = (str - base.str) + (dex - base.dex) + (vit - base.vit) + (energy - base.energy)`,
그 후 네 스탯을 `base` 값으로 덮어쓰고 `_stat_points += stat_refund`.

### 5.2 스킬 환불

`_player.skills`의 4개 슬롯을 순회하며 레벨이 1보다 크면 `(레벨 - 1)`을 환불하고 레벨을
1로 설정한다. 레벨이 0이거나 1인 슬롯은 그대로 둔다(0=미해금 유지, 1=이미 기준치).

### 5.3 비용

`300 + 플레이어 레벨 * 60` — 도박(`_gamble_cost`: `200 + lvl*45`)보다 약간 비싼 1회성
목적 비용. 골드 부족 시 다른 상인 버튼(물약 구매 등)과 동일하게 버튼을 막지 않고 로그만
남긴다.

### 5.4 검증

- `_run_respec_test()`: 스탯 포인트 4개를 vit/str에 분배 → 기준값+2 확인, 스타터 스킬에
  포인트 3개 투자 → 레벨4 확인 → 골드 지급 후 `_respec()` 호출 → 스탯이 기준값으로,
  스타터 스킬이 레벨1로, 포인트 풀이 각각 4/3으로 환불, 골드가 비용만큼 차감, 환불된
  포인트로 재분배 가능한지까지 확인 후 `[RESPEC] ... verdict=` 출력.
- barb/sorc 50초 오토퀴트에는 묶지 않음(경제/자동장착 테스트와 동일하게 전용 모드로 분리,
  기존 50초 플레이 경로와 겹치지 않는 결정론적 검증이라 별도 실행이 더 명확함).
