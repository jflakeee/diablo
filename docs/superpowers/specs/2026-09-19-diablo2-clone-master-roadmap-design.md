# 디아블로 2 클론 (모바일) — 마스터 설계·분해 로드맵

- 작성일: 2026-09-19
- 상태: 설계 승인됨 (구현 미착수)
- 관련 문서: [D2 메커니즘 딥리서치](../research/2026-09-19-diablo2-mechanics-research.md)

---

## 1. 목표와 범위

원본 디아블로 2 (LoD 확장팩 포함)의 **게임 시스템·수치를 동일하게** 재현하되, **디자인 자산과 일부 요소는 모바일에 맞게 다르게** 구현하는 클론을 만든다.

이 문서는 **코딩 산출물이 아니라**, 풀 클론을 독립적으로 구현 가능한 하위 프로젝트로 **분해한 로드맵**이다. 각 하위 프로젝트는 이후 별도의 스펙 → 플랜 → 구현 사이클을 갖는다.

### 이번 단계의 산출물
1. 본 마스터 로드맵 문서
2. D2 메커니즘 딥리서치 문서 (정확 수치·공식·출처)

실제 게임 코드는 이 두 문서가 확정된 뒤, 하위 프로젝트 단위로 착수한다.

---

## 2. 설계 검토 기록 (중요)

초기 아이디어 문서는 "디아블로 **1**과 동일"이라고 기술했으나, "동일 구현 목록"에 **보석(소켓)·룬워드·큐빙(호라드릭 큐브)·스킬트리**가 포함되어 있었다. 이 4가지는 **모두 디아블로 2 기능**이며 디아블로 1에는 존재하지 않는다(D1은 스킬트리 대신 스펠북으로 마법을 학습하고, 소켓/룬워드/큐브가 없음).

→ 사용자 확정: **대상은 디아블로 2**. 아이디어 문서를 D2 기준으로 수정하여 모순 해소.

이 검토는 하위 시스템 전체 설계의 전제이므로 기록으로 남긴다.

## 4. 하위 프로젝트 분해

각 하위 프로젝트는 (a) 하는 일, (b) 인터페이스, (c) 의존성을 명확히 갖는 단위로 정의한다.

### 기반 레이어

**P0 — 코어 엔진 & 렌더링**
- 하는 일: 게임 루프(fixed timestep), 아이소메트릭 렌더러, 에셋 파이프라인, 카메라, 모바일 입력(가상 조이스틱 + 스킬 버튼 + 탭 이동)
- 인터페이스: `GameLoop`, `Renderer.draw(entity)`, `Input.getIntent()`
- 의존성: 없음 (기반)

**P1 — 맵/레벨 시스템**
- 하는 일: D2식 랜덤 던전 생성(프리셋 타일 조각 + 랜덤 배치/연결), 타일셋, 충돌 그리드, 경로탐색(A*), 미니맵, 워프/입구
- 인터페이스: `LevelGenerator.generate(seed, actLevelDef) → Level`, `Level.isWalkable(x,y)`
- 의존성: P0

### 캐릭터·전투 레이어

**P2 — 엔티티·스탯·전투 코어**
- 하는 일: 엔티티 모델, 4대 속성(str/dex/vit/energy), 레벨링, 파생스탯(life/mana/stamina), 데미지 계산, 명중(AR vs Defense)·블록·방어 공식, 저항, 상태이상
- 인터페이스: `Combat.resolveAttack(attacker, defender, skill) → result`, `Stats.derive(base)`
- 의존성: P0 / 딥리서치(전투 공식)

**P3 — 스킬 시스템**
- 하는 일: 클래스별 스킬트리, 스킬 레벨, 시너지, 마나 코스트, 쿨다운, 스킬→전투 효과 연결. 바바리안부터, 이후 클래스 확장.
- 인터페이스: `SkillTree(classDef)`, `Skill.cast(caster, target) → effects`
- 의존성: P2 / 딥리서치(스킬 시너지)

### 아이템 레이어

**P4 — 아이템·접사 시스템**
- 하는 일: 베이스 아이템 정의(무기/방어구/기타), 아이템 분류(normal/exceptional/elite × normal/magic/rare/set/unique), prefix/suffix 접사 테이블, ilvl/alvl 기반 접사 롤링, 스탯 부여
- 인터페이스: `ItemFactory.roll(baseItem, ilvl, quality) → Item`
- 의존성: P2 / 딥리서치(접사 시스템)

**P5 — 소켓·보석·룬워드·큐빙**
- 하는 일: 소켓팅, 보석/룬 삽입, 룬워드 조합 판정, 호라드릭 큐브 레시피 엔진
- 인터페이스: `Socketing.insert(item, gem)`, `Runeword.match(item, runes)`, `Cube.transmute(inputs) → outputs`
- 의존성: P4 / 딥리서치(룬워드·큐브 레시피)

**P6 — 드롭 시스템**
- 하는 일: 트레저 클래스(TC) 트리, 몬스터/난이도별 드롭 확률, 아이템 레벨 산정, No-Drop 확률, 골드 드롭
- 인터페이스: `DropTable.roll(monster, difficulty, playerCount) → items`
- 의존성: P4, P7 / 딥리서치(드롭·TC)

### 월드·콘텐츠 레이어

**P7 — 몬스터·AI**
- 하는 일: 몬스터 스탯·저항·속성, AI 행동(추적/원거리/도주/소환), 유니크/챔피언 몬스터 접사, 난이도·인원수별 스케일링
- 인터페이스: `Monster(def)`, `MonsterAI.tick(monster, world)`
- 의존성: P2, P1 / 딥리서치(몬스터 스탯·AI)

**P8 — 보스·액트1 콘텐츠**
- 하는 일: 보스 특수 공격 루틴(Andariel 등), 퀘스트 스크립트, NPC, 상점/도박, 액트1 구역·워프 구성
- 인터페이스: `Boss.attackRoutine()`, `Quest`, `Vendor`
- 의존성: P7, P1, P4

### 메타·UI 레이어

**P9 — 모바일 UI/UX**
- 하는 일: HUD(생명/마나 구슬), 인벤토리 그리드(드래그&드롭), 스킬 배치 슬롯, 창고, 캐릭터/스킬 화면, 툴팁. 터치 최적화.
- 인터페이스: UI 컴포넌트, 게임 상태 바인딩
- 의존성: P2, P3, P4

**P10 — 세이브·오디오**
- 하는 일: 캐릭터/월드 직렬화, 로컬 세이브, 오디오 매니저(오리지널 사운드)
- 의존성: 전 레이어

### 온라인 레이어 (후반)

**P11 — 계정·서버 백엔드** / **P12 — 멀티 동기화** / **P13 — 거래 시스템**
- 하는 일: 계정, 권위 서버, 상태 동기화, 안전 거래
- 의존성: P0~P10 완성 후

## 5. 의존성 순서 로드맵 (페이징)

```
Phase 0  기술스택 확정 + 프로토타입   →  P0 (렌더/입력/루프)
Phase 1  움직임 + 단일 맵 + 몬스터1 + 기본공격  →  P1 + P2(최소)
Phase 2  캐릭터 + 바바리안 스킬트리   →  P2 + P3
Phase 3  아이템 + 접사 + 드롭 + 인벤토리  →  P4 + P6 + P9(인벤토리)
Phase 4  소켓/보석/룬워드/큐브   →  P5
Phase 5  몬스터 다양화 + AI + 보스 + 액트1  →  P7 + P8
Phase 6  콘텐츠 확장 (추가 클래스, 액트2~5)  →  P3/P7/P8 반복
Phase 7  온라인 (계정, 거래, 멀티)   →  P11 + P12 + P13
```

- **수직 슬라이스 완료 지점 = Phase 3 끝** ("게임이 돈다" 증명: 이동→전투→드롭→장착).
- Phase 4~5로 D2 특유의 깊이(빌드 다양성) 확보.
- Phase 6~7은 장기 확장.

## 7. 기술 스택 — 확정: **Godot 4** (2026-09-19 갱신)

### 결정 배경 (제약 변경)
초기엔 웹(htdocs) 배포를 전제로 Phaser 3를 추천했으나, 사용자가 조건을 변경:
- **웹 배포 제약 제거** · **네이티브 성능 최우선** · **저사양 개발 환경 고려**.

→ 재평가 결과 **Godot 4로 확정**(에디터 생산성으로 방대한 D2 콘텐츠 관리). 상세 근거·후보 비교는 [딥리서치 Part 8](../research/2026-09-19-diablo2-mechanics-research-part8.md).

### ⚠️ 개발 머신 제약이 결정을 지배한다
실측: **i5-3360M(2C/4T) · 8GB · Intel HD 4000 · Win10**.
- **HD 4000은 Vulkan 미지원**(Gen9/Skylake+만 가능) → **Godot 4 기본(Forward+)·Mobile 렌더러 구동 불가**.
- HD 4000은 OpenGL 4.0까지 지원하나, **Intel 드라이버의 OpenGL 3.3 지원이 불완전**(알려진 이슈)라 Godot 4 Compatibility 렌더러도 **불안정 가능성**.

### 확정 구성 & 완화책
| 항목 | 결정 |
|------|------|
| 엔진 | **Godot 4.4.x** (개선된 TileMapLayer y-sort 포함) |
| 렌더러 | **Compatibility (OpenGL3)** 강제 — `--rendering-driver opengl3`, 프로젝트 렌더링 방식 "Compatibility" |
| 대비책 | 4.4가 이 머신에서 불안정하면 **Godot 3.6(GLES2 폴백)** 로 프로토타입 후 4.x 이전 |
| 언어 | GDScript 우선(반복 빠름), 성능 핫스팟만 C#/GDExtension |
| 중요 사실 | **HD 4000 제약은 "개발 머신" 한정** — 출시 타깃(모바일/최신폰)은 GLES3/Vulkan 정상 지원, 제품 성능엔 영향 없음 |

### P0 최우선 디리스크 태스크 (조사 아닌 실측)
1. 이 머신에서 **Godot 4.4 `opengl3` 에디터 구동 + 2D 아이소 씬 편집 안정성** 스모크 테스트.
2. **아이소 TileMapLayer + y-sort + 200 스프라이트 60fps** 실측 (Part 2 §5·Part 7 §3 리스크 검증).
3. 실패 시 즉시 **Godot 3.6 폴백** 판단.

> 후보 비교(MonoGame/raylib/LÖVE 등)와 저사양 상세 분석은 Part 8 참조. 최종 선택은 **에디터 생산성 우선**이라는 사용자 결정에 따름.

## 8. 모바일 UI/UX 전략

원작은 마우스(좌클릭 이동/공격, 우클릭 스킬) 기반이라 터치 이식이 최대 UX 과제.

- **이동:** 가상 조이스틱(좌하단) 또는 탭-투-무브 중 택1 또는 병행. Diablo Immortal은 조이스틱 채택 → 벤치마크.
- **공격/스킬:** 우하단 스킬 버튼 4~6개 + 기본공격 버튼. 롱프레스로 스킬 배치 변경.
- **타겟팅:** 자동 타겟(가장 가까운 적) + 방향 조준 혼합.
- **인벤토리:** D2 그리드 유지하되 칸 크기 확대, 드래그&드롭 + 롱프레스 컨텍스트 메뉴.
- **물약:** 벨트 슬롯 → 화면 상시 버튼으로 노출.
- **해상도:** 세로/가로 모드 결정 필요(가로 권장 — 아이소메트릭 시야 확보).

이 전략은 P9에서 별도 상세 스펙으로 확장한다.

## 9. 자산·저작권 방침

- **코드와 수치(공식/테이블/확률)는 재현 대상** — 게임 메커니즘은 저작 보호 대상이 아님.
- **모든 시각/청각 자산은 오리지널 신규 제작** — 원본 스프라이트·사운드·맵·스토리·캐릭터 미사용. 아이디어 문서의 "다르게 구현" 항목과 일치.
- 클래스/아이템/몬스터의 **고유 명칭**도 오리지널로 대체 검토(상표 리스크 회피).
